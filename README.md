# Evaluating synthetic healthcare event logs

Code and results for *Temporal Performance Analysis of Synthetic Healthcare Event
Logs Using Process Mining* (Nath, Friedrich and Pelka).

The study tests whether the aggregate fidelity measures ordinarily used to judge
synthetic event logs support process-level analysis. Three generators — a
first-order Markov model, a baseline without sequence conditioning, and a trace
bootstrap that copies whole calibration encounters — are compared under
development-sample, patient-held-out and temporal evaluation, with disclosure
indicators reported alongside fidelity.

## Data availability

The clinical source data used for calibration are pseudonymised inpatient records
from University Hospital Essen, held under ethics approval 2110391BO and subject
to institutional access restrictions. **They are not in this repository and cannot
be released.**

The synthetic event log analysed in the paper is included under `data/`. It
contains no real patient records and no one-to-one correspondence with any real
patient.

`.gitignore` blocks the source export and every partition derived from it. Do not
weaken those patterns.

## Reproducing the results

The steps below require the clinical source export, which is not distributable.
Researchers without access can inspect the released synthetic log and the
aggregate results, and can exercise the full pipeline on a schema-compatible fake
input generated by `scripts/make_fake_source.py`.

### 1. Generate a synthetic log under one evaluation condition

```bash
python scripts/generate_synthetic_heldout.py \
    --input new_dataset.csv --out runs/patient_markov \
    --split patient --calibration-fraction 0.7 --split-seed 7 \
    --activity-model markov --seed 20260915
```

`--split` takes `patient`, `temporal` or `none`. `--activity-model` takes
`markov`, `independent` or `trace`.

### 2. Evaluate against the held-out partition

```bash
python scripts/evaluate_synthetic_logs.py \
    --source runs/patient_markov/evaluation_source.csv \
    --synthetic runs/patient_markov/synthetic.csv \
    --out eval/patient_markov --tie-repeats 100 --bootstrap 1000
```

### 3. Disclosure measures

```bash
python scripts/disclosure_metrics.py \
    --calibration runs/patient_markov/calibration_source.csv \
    --holdout runs/patient_markov/evaluation_source.csv \
    --synthetic runs/patient_markov/synthetic.csv \
    --out results/disclosure_patient.json
```

### 4. Full sweep

Three conditions, three generators, 30 generation seeds, evaluated before and
after timing calibration.

```bash
python scripts/run_heldout_experiment.py \
    --input new_dataset.csv --out heldout_experiment \
    --seeds 30 --first-seed 20260915 --split-seed 7 \
    --splits patient temporal none
```

Repeat with `--split-seed 11` and `--split-seed 23`, `--splits patient`, for the
patient-partition replication reported in the paper.

### 5. Figures

```bash
python scripts/make_new_figures.py --runs heldout_experiment/heldout_runs.csv --out figures
python scripts/make_splitseed_figure.py \
    --runs heldout_runs_seed07.csv heldout_runs_seed11.csv heldout_runs_seed23.csv \
    --seeds 7 11 23 --out figures
```

## Seeds

| Purpose | Value |
|---|---|
| Generation | 20260915–20260944 |
| Patient partitions | 7, 11, 23 |
| Temporal partition | 7 |
| Tie randomisation and bootstrap | 20260917 |

Temporal cutoff: 1 January 2024, applied to each patient's first admission.

## Scripts

| File | Purpose |
|---|---|
| `generate_synthetic_heldout.py` | Partitions the source, fits on the calibration partition only, generates a cohort matched to the evaluation partition |
| `evaluate_synthetic_logs.py` | Structural and timing fidelity, tie-ordering and support sensitivity, patient-cluster bootstrap |
| `disclosure_metrics.py` | Copy rates and distance to closest record, with the real held-out baseline |
| `run_heldout_experiment.py` | Sweeps conditions, generators and seeds |
| `make_new_figures.py` | Condition and disclosure figures |
| `make_splitseed_figure.py` | Patient-partition robustness figure |
| `make_fake_source.py` | Schema-compatible fake input for testing without the real export |
